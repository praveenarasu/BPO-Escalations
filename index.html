BPO Escalations Knowledge Base

Authoritative instructions for analysing an uploaded Excel workbook and producing a new, formatted Excel workbook.

Workbook and output requirements

  • The source workbook has two tabs: Query data and Non-callable payer List.
  • Preserve the original data and add these columns to the output: Recommended action, Rework marker, and Possible paper drop.
  • Use a dark blue header for all three new columns. Fill Recommended action yellow, Rework marker light green, and Possible paper drop grey.
  • Evaluate the rules below per CLAIMID. Values containing a code may be delimited; match approved codes as codes, not as arbitrary substrings.

Approved kick code list

ACSRULERVW, AGECPTMATCH, AGEDXMATCH, AMCSACODERVW, AMCSCCODERVW, AMCSGCODERVW, AMCSOCODERVW, ATHCODERULERVW, ATHCODERVW, ATHCODEXFR, CBOCODERVW, CODINGRVW, CPT, DIAGNOSIS, DMCODINGCHANGE, DMCODINGRVW, DRGCODE, DXCPTMATCH, GENDERCPTMATCH, GENDERDXMATCH, LCDNCD, MODCPTMATCH, MODIFIER, NDCHCPCROSSWALK, NEWPATIENT, POS, POSCPTMATCH, PRINCPLPROC, PTREASON4VISIT, RECODEOVERRIDE, RECODERVW, REVCODE, REVCPTMATCH, TOB, TOBREVCODEMATCH, TOBVALCODEMATCH

Only these codes may be selected by the recommendation logic. The values DRPCBOAPPROVE, MANAGER, and COMPLEX are rule outcomes and are also valid output values.

Recommended action

Apply the following rules in order for each CLAIMID. The first applicable result wins.

Condition 1: coding changes require approval

If ERA_EOB_POSTED = Yes, inspect ERA_EOB_CODE_PAIRS. If it contains an approved kick code, continue. If CODING_CHANGES_PRESENT = Yes, or CODING_CHANGES_FIELDS has a value, or either VOIDED_PROCEDURECODE or CREATED_PROCEDURECODE has a value, set Recommended action = DRPCBOAPPROVE.

If ERA_EOB_POSTED = No, inspect REJECTION_YN and these columns: REJECTION_KICKCODE, REJECTION_ATHENAKICKCODE, PREVIOUS_ACTIONTOINFLOW, PREVIOUS_ATHENAKICKCODETOINFLOW, PREVIOUS_KICKCODETOINFLOW_, and PREVIOUS_KICKCODETOINFLOW_REMARKCODES. If any contains an approved kick code and the same coding-change test is true, set DRPCBOAPPROVE.

Condition 2: no coding change

Use the same ERA/EOB or rejection-code selection above. If the coding-change test is false (coding changes are not present, coding-change fields are empty, and both procedure-code fields are empty), inspect INFLOW_QUEUE_COUNT. When it is 0, recommend one approved code from the applicable source column.

Exception: if ERA_EOB_CODE_PAIRS contains CO204:NCPREVIEW, recommend CODINGRVW. If PREVIOUS_KICKCODETOINFLOW_REMARKCODES contains a code ending in 507 and IRC_GROUP_NAME starts with Medicare, recommend CODINGRVW.

Conditions 3 and 4

Apply Condition 1, then Condition 2 if Condition 1 does not qualify. For Condition 3, an otherwise eligible INFLOW_QUEUE_COUNT = 1 produces CODINGRVW. For Condition 4, an otherwise eligible INFLOW_QUEUE_COUNT = 2 produces MANAGER.

Final fallback: if no condition applies, set Recommended action = COMPLEX.

Possible paper drop

For each claim, check ERA_EOB_POSTED. When it is No, apply the rejection logic described for Recommended action. Then inspect IRC_GROUP_NAME. If it contains Blue or Commercial, set Possible paper drop = Yes. Otherwise leave it blank or use the workbook's established false-value convention.

Rework marker

Set Rework marker = Yes only when all three conditions are true:

  1. ERA_EOB_POSTED = Yes.
  2. The INSURANCEREPORTINGCATEGORYNAME value in Query data does not exist in the IRC column of Non-callable payer List.
  3. USERNOTES_AFTER_INFLOW contains either coded correctly or reach payer (case-insensitive).

Agent implementation guidance

Keep source values intact, treat blank and missing values as no value, compare Yes/No values case-insensitively, and preserve the original tab names. Do not invent kick codes. When multiple approved codes are available, select the first one in source-column order and preserve the source order within a cell unless an exception overrides it.
